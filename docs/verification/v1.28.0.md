## Measured, not assumed

**The catalog installs, and installs once.** `a_clean_machine_installs_every_pack`
points `APPDATA` at a temporary directory and runs the real `install_missing()`:
**133 packs in 2.30 s**, every one with both an arrow and a hand. A second call
costs **3.2 ms**.

That second number is the one this release needed most. All fifty new archives
came from a site that names every download "… Cursor", and `pretty_folder_name`
strips a trailing "Cursor" — so a label pasted straight from the filename
installs to a directory the launch check does not look in, and the pack is
unpacked and re-imported on every launch for the life of the install. Nothing
logs it and nothing breaks. 3.2 ms is the proof it is not happening.

**Windows accepts every bundled cursor.** `windows_accepts_every_bundled_cursor`
puts every file in all 133 archives through the same `LoadCursorFromFileW` the
importer uses, so an `.ani` is proved to animate rather than proved to yield one
still frame.

**Every shipped animation has frames to play.** New test. The animated preview is
worth nothing if the files decode to a single frame, and a one-frame `.ani`
animates exactly as much as the still it replaced. Every `.ani` in the catalog
decodes to more than one frame.

**The two-cursor packs still fill two roles.** `a_two_cursor_pack_fills_two_roles`
covers all 133. This is the trap that made `Minecraft Steve Raising Hands` install
with no pointer: the importer reads a role out of the whole filename stem and
checks "hand" before "cursor", so an arrow named `...Hands--cursor--...` claims
the hand and collides with the real one. All fifty new archives were rewritten to
`arrow-role` / `hand-role` before being embedded.

**No uncredited pack carries a name inside its animation.**
`an_uncredited_cursors_only_pack_carries_no_name_inside_its_animation`, plus a
second test asserting the fifty-slug credit exemption names packs that actually
ship. The exemption exists because the new packs' sources *are* credited, on the
website; the forty-seven given directly with no credit asked for are still
checked exactly as before.

**The catalog spreads across its shelves.** `the_shipped_catalog_is_spread_across_the_shelves`
reads the real labels out of `bundled.rs` and asserts every named category has
something on it and that OTHER holds under a quarter of the catalog. Measured:
ANIME 28, GAMING 24, CUTE 17, MEMES 15, OTHER 14, MOVIES & TV 13, CARS 7,
SPORTS 5, WEAPONS 5, TECH 5.

**A pack id cannot be resolved without branching.**
`nothing_outside_the_catalog_resolves_a_pack_id_without_branching` scans every
`.rs` file outside `commands.rs` and `catalog.rs` for a direct
`catalog::build_roles(` call. That function resolves a *generated* pack and
answers `UnknownPack` for the `user:` ids the entire shipped catalog uses — and
two callers were doing exactly that. See below.

**Deriving the category rather than trusting `pack.json` was load-bearing, and
the number says so.** On this machine's installed catalog, **36 of the 133**
packs still have `OPTIMAL CURSED` written into their `pack.json` — they were
installed by an earlier build, and `install_missing()` skips a pack that is
already there, so nothing rewrites them. Read through `shelf_for`, all 36
re-derive and every one of the 133 lands on a named shelf; the live distribution
is identical to the test's. Had the stored value been trusted, a quarter of the
catalog would have sat on a shelf that is not in the filter row at all, and no
chip would have reached it.

**Observed on a running dev build**, from its own log rather than inferred: all
133 packs installed on first launch, applies committed, and photo mode loaded its
runtime in 98 ms and removed 62% of a photograph's background in 1535 ms.

## The two failures this release fixes that nothing was reporting

Both were found by reading, then confirmed against a real log line and a real
`applied.json` on this machine.

**Size, colour and outline did nothing for any catalog cursor.**
`session::reapply_with_appearance` called `catalog::build_roles` with the saved
pack id. Every shipped pack's id is `user:…`, which that function cannot resolve,
so the call returned `UnknownPack` — logged once as *"settings saved, but the
cursor could not be redrawn: No cursor pack with that id is installed."* and
otherwise swallowed. The slider moved and the pointer did not.

**Last session's cursor was never adopted at launch.** `session::restore` failed
the same way, on the same ids. Nothing was recorded as applied, so the watchdog
had no scheme to defend and the home screen fell back to reading a name out of
the registry. The cursor on screen after a restart was last session's only
because Windows loads `HKCU\Control Panel\Cursors` at sign-in — not because this
app had done anything.

Both now go through `commands::build_pack_set`, which is the one place that
branches on imported versus generated, and the location test above is what stops
a third caller reintroducing it.

## Verified after publishing, on the real install

Both of these were written below as "not verified" and then happened on their
own, on this machine, within ten minutes of the release going out.

**An N → N+1 update.** The installed 1.27.0 picked up 1.28.0 through the ordinary
background updater and restarted into it — the first time that path has actually
been exercised in this project rather than reasoned about. The new build then
installed the 50 new packs on its first run, claimed the pointer, and logged no
error or warning at any point.

**Background removal from an actual install**, which the 1.27.0 record also had
to leave unverified. Photo mode loaded its runtime from the installed location,
`%LOCALAPPDATA%\Cursed\photo\onnxruntime-x64.dll`, and cut a photograph twice:
**62% removed in 291 ms and 170 ms**, against 1535 ms for the first cut on the
dev build. The simple keyer refused that image first, correctly, which is the
escalation path working end to end.

## Not verified

- **The uninstall gate.** `scripts/verify-uninstall.ps1` needs a machine that can
  be installed to and rolled back. It was not run: the only Windows machine here
  is the author's working one, with a released copy of Cursed installed and in
  use, and the check requires installing over it and then uninstalling. This is
  the check that asserts all seventeen pointer roles come back byte-identical.
- **A restart.** Item 2 of this release is about what happens at sign-in, and the
  fix is reasoned from the code and the log rather than observed across an actual
  reboot.
- **ARM64 and 32-bit on real hardware.** As every release: only the PE machine
  type is ever checked.
- **The re-rendered artwork judged by eye.** Imported cursors are now re-rendered
  at the requested size through `build::rescale`, and the ladder, the hotspot
  scaling and the refusal paths are covered by tests — but nobody has looked at a
  133-pack catalog at 128 px and said whether it looks right.
