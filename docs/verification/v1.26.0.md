# v1.26.0 — verification record

What was checked, what was not, and what could not be. Written to the standard
in `README.md` in this directory.

Machine: Windows 11 Home, build 26200, x64, 24 logical processors. Two BenQ/Acer
panels, both **native 1920x1080 running at 1920x1080**, system DPI 96,
`TextScaleFactor` unset.

## How this release was found, which is the part worth keeping

One machine reported cursors that looked pixelated and blocky. Over several
rounds the cause was guessed at from the code and the guesses were wrong, in
order: stale cache, render time, a size Windows had to stretch, `glyph_size`
applied twice, the watchdog fighting the live layer. Each was eliminated by a
measurement, and none of them was it.

What actually moved the diagnosis was the reporter noticing that **the blur
lasted exactly as long as the app held focus**. That is a statement about the
preview path, and no amount of reading the renderer would have produced it.

The lesson is written into the tools rather than into a comment:
`cursorprobe`, `matteprobe` and `livewatch` exist so the next report starts with
a measurement.

## Fixed, with the evidence for each

| Fix | Evidence it was real |
| --- | --- |
| Preview and commit build the same set | Symptom tracked window focus exactly; `build_preview_set` built the arrow alone |
| The front end's size is snapped to a rung | `commands::effective_size` clamped and returned; 1.25.0 snapped the other two entry points |
| Cache key fingerprints the ladder | `v2-ffffff-o/Arrow.cur` dated 2026-08-21 carried 8 rungs; 1.24.0 published on the 23rd |
| Custom cursors stop at what the source can fill | Applied cursor built from a **37x37, 144-byte** source, written out to 256 px, file 550 KB |
| Single-entry imports rebuilt onto the ladder | 3 of 50 static cursors in the reporting library had one entry |
| Thumbnails resampled by us, at 128 px | `import::preview` called `cur_reader::read`, i.e. `LoadImageW`, i.e. Windows' bilinear |
| Apply claims the pointer lock, preview stands down | Two channels registered at login; `watchdog.rs` asked, apply and preview never did |

## The machine state, since the report was machine-specific

- **Two autostart entries**, one of them `Cursed Dev` pointing at
  `src-tauri\target\debug\cursorforge.exe` — a binary rebuilt by any
  `cargo build`. Its own log shows it last ran on 2026-08-23, the day the reports
  began. Removed.
- **An unbroken chain of in-place updates** from 1.19.0. Never a clean install,
  which is exactly the state that accumulates a stale cache.
- **Windows-side settings, all checked and all normal**: cursor shadow **off**
  (`UserPreferencesMask` byte 1 bit 0x20 clear), `MouseTrails` 0,
  `VisualFXSetting` 3, `CursorBaseSize` 32, `SM_CXCURSOR` 32, no display scaling
  and no non-native resolution. Nothing on the Windows side degrades a cursor on
  this machine.

## The audit that found nothing, recorded so it is not redone

- `bitmap.rs:162` is the only resize in the shipped pipeline:
  `ResizeAlg::Convolution(FilterType::Lanczos3)`, linear light, premultiplied
  alpha. Every nearest-neighbour in the tree is in `genpacks`, deliberate, and
  developer-only.
- Nothing caps resolution at 16 or 32. The ladder reaches 256, the format's own
  ceiling.
- Read out of a generated file: 32 bpp, `BI_RGB`, no palette, no compression,
  55 distinct alpha levels across a 32 px entry.
- `write_cur` enforces 1-256 per entry and encodes 256 as 0, as the format
  requires.

## Not verified

- **Whether this fixes what was reported.** Six defects were found and fixed and
  every one is real, but the reporter was still seeing the problem after five of
  them. The honest position is that this release removes six causes, not that it
  removes the symptom. That will be known when it is installed and looked at.
- **The two manual looks** added to the standing gate in v1.24.0 — a large
  accessibility pointer, and a photo cut-out against white. Three releases old
  now and still never performed. Every defect above was found by measuring a
  file; the two things that need an eye on a screen remain the gap.
- **An N to N+1 update on a clean VM**, and **ARM64 / 32-bit on real hardware**.
  Unchanged, and still never run.
