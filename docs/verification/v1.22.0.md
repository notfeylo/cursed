## The import path, against real files

The reader is new (`build/icon_reader.rs`), so it is measured against files
nobody here wrote.

| Check | Result |
| --- | --- |
| Every `.cur` and `.ani` in `C:\Windows\Cursors` | **189 of 189** decode |

| 60 alternating PNG / `.ani` staging round trips | 3.0 s, GDI +0 |

The four that used to fail are recorded because they are the interesting ones:
`cross_l.cur`, `cross_m.cur`, `lcross.cur` and `libeam.cur` are monochrome and
drawn almost entirely with the AND=1/XOR=1 "invert the screen" state. They
decoded to a completely transparent image and the import failed one step later
with a message pointing at the wrong module. See `docs/CURSOR_FORMAT.md`.

## Not verified

- **ARM64 and 32-bit on real hardware of those architectures.** Still only the
  PE machine type is checked. Unchanged from every previous release.
- **An N → N+1 update on a clean VM.** The silent-update path (`/UPDATE /S /R
  /NS`) has still never been run end to end on a machine that was not this one.
  §2.5 of the update brief remains open, and it is the largest gap here.
- **The installer-launch failure path.** `abort_shutdown` is unit-tested for
  ordering and reachability; nothing has actually had an installer refused by a
  scanner and watched the app come back.
- **The Windows 1803 floor.** The silent branch past the message box is asserted
  by reading the hook, not by running the installer on a PC below build 17134 —
  there is no such machine here.
- **Photo mode on ARM64 or 32-bit.** The artifacts exist and are checksummed;
  only the x64 runtime has been loaded and run.
- **Photo mode over an animation.** One inference per frame is correct and
  tested on stills; a 60-frame source has not been timed, and the UI shows no
  progress while it runs.
